## Intended use

Detect anomalous windows in **synthetic** OT telemetry from the
`ot-security-lab` water-intake simulation, as the trigger for a RAG + LLM triage
prototype. The model produces an ordinal `decision_function` score; negative
values are more anomalous. It is not a safety instrumented system and must not
be used to make physical control decisions.

## Training data

| Field | Value |
| :--- | :--- |
| Source | `data/train/telemetry.csv` (generated by `scripts/generate_telemetry.py`, seed 42) |
| Rows | 180 (15 minutes at 5-second polling) |
| Content | Normal operation only, no injected anomalies |
| Features | 15 engineered features over 6-row (30 s) windows, stride 1 → 175 windows |
| Registers | `reg_0` inlet valve, `reg_5` tank level; regs 1–4 constant |
| Split | Train on normal-only data; evaluate on `data/test` (240 rows, 5 injected anomaly classes) |

## Features actually used

The feature vector has 15 columns, but the training data contains **constant
values** for the valve, function-code and source-IP groups. `StandardScaler`
leaves them at scale 1 and the Isolation Forest never splits on them. Tree
inspection (`security/evals/evasion_experiment.py`) shows:

| Group | Features | Trees using them (of 100) |
| :--- | :--- | --: |
| Tank level | mean, std, min, max, last, rate of change | 99–100 each |
| Valve | mean, std, last, changed | **0** |
| Modbus | fc_3, fc_6, fc_131, has_write_fc | **0** |
| Source | is_known_good_ip | **0** |

**Implication:** the committed artifact is effectively a tank-level anomaly
detector. It cannot use Modbus metadata or source identity, so claims that
`has_write_fc` or `is_known_good_ip` make writes/scans trivially detectable do
not hold for this model. Fixing this requires training data in which those
features vary (authorized writes, background scans, multiple sources) or
explicit rules.

## Evaluation

Ground truth: 20 windows whose end timestamp falls inside an annotation interval
(`data/test/annotations.csv`). Metrics at the default `predict()` boundary:

| Metric | Value |
| :--- | --: |
| Precision | **0.188** |
| Recall | **0.650** |
| F1 | **0.292** |
| TP / FP / FN | 13 / 56 / 7 |

Per class, `predict()`:

| Class | Detected / ground truth |
| :--- | :--- |
| Scanning | 5 / 5 |
| Physics violation | 4 / 4 |
| Cavitation | 4 / 4 |
| Overfill | **0 / 4** |
| Unauthorized write | **0 / 3** |

The documented threshold `-0.03` flags 50 windows and gives precision 0.220 /
recall 0.550 on the same ground truth. The best achievable precision over all
thresholds on the committed scores is 0.229; see `10-repro-audit.md` in the
interview-prep pack for the full calculation. Scanning detection is a tank-pattern
coincidence, not Modbus awareness (see the evasion results).

## Security evaluation

| Experiment | Result | File |
| :--- | :--- | :--- |
| Slow overfill drift | **0** dangerous windows detected at every ramp rate; 0/15 at the final 95% plateau | `security/evals/evasion_results.md` |
| Slow cavitation drift | detected once tank min ≤ 15%, with early false alarms on the ramp | same |
| Low-rate scan (1 exception per 6-row window) | **1–2 detections out of 55–595 malicious windows**, regardless of source IP | same |
| Poisoning (5% anomaly-shaped training windows) | recall 0.215; scanning 32%, cavitation 62%, physics 5% | `security/evals/poisoning_results.md` |
| Poisoning (10%) | recall 0.130; scanning 6%, cavitation 42% | same |

## Limitations

- Synthetic data and scripted anomalies; no field performance claim.
- Small dataset (175 training windows); threshold and metrics are unstable.
- Nine of 15 features are dead due to zero variance in training.
- Overfill and unauthorized-write classes are missed entirely.
- Threshold tuned by hand; no validation split; test-set tuning is a known
  methodological weakness.
- The model artifact was trained with scikit-learn 1.8.0 and unpickles with an
  `InconsistentVersionWarning` on 1.9.0. The manifest pins the artifact hash but
  not the runtime version.
- Pickle/joblib is a trusted-artifact format; the hash check is the control.
  Prefer skops/ONNX in a production supply chain.

## Ethical and operational notes

- The model is advisory. A human reviews every report and stages every rule.
- The pipeline must not write to PLCs or deploy rules automatically.
- Do not use synthetic metrics to justify production deployment; collect
  labelled normal and attack telemetry from the target environment.
